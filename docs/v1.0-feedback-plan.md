## F1 Solo Leg (501): match and leg average, fewer stats on screen

**What you asked for**
- ✅ Two averages: **Match average** goes on over all legs of the game, **Leg average** starts again with each leg.
- ✅ 80+ / 100+ / 140+ / 180 are no longer shown in the routine. They are saved, and listed in the result screen.
- ✅ Don't put more on the screen than needed.

**How it works today** (`src/lib/games/solo-leg.ts`, `src/lib/games/x01.ts`)
- The panel shows a 3-dart average over all legs (already the match average, just named "3-dart average"), first 9
  average, legs, darts per leg, best leg, checkout rate, highest checkout, 100+, 140+, 180.
- There is no leg average and no 80+ count. `playLegs` does not keep points per leg.
- Every line in `lines` is shown in the panel *and* in the result screen's stats table, and saved with the result.

**Plan**
1. `x01.ts`: keep points per leg. `Leg` gets `points`; the state gets `legPoints` for the leg being played. Add
   `eighties` (visits 80–99), next to `tons` (100–139), `ton40s` (140–179) and `oneEighties`.
2. `solo-leg.ts`:
   - The hero line becomes **"Match average"** (DE "Match-Average"). Same number as today, so the history and the DPI
     don't change. One match = one Solo Leg game; two Solo Legs in a routine each have their own.
   - New line **"Leg average"** right under the hero: points ÷ darts × 3 of the leg being played, the turn on the
     board included. During the Game shot (F2) it still shows the leg that was just won; it starts again with the
     first dart of the next leg.
   - Save `eighties` and `bestLegAverage` in `values`. The result screen shows "Best leg average" instead of a leg
     average, which means nothing once the game is over.
3. `types.ts`: a `StatLine` gets `live?: false`. Those lines are left out of the routine panel (`App.svelte`,
   `others`) but stay in the result screen's stats table and in the saved result. 80+, 100+, 140+ and 180 get it.
4. Tests: per-leg points with busts and the turn on the board, the 80+ bucket, the leg average starting again.
5. EN/DE texts, README row for Solo Leg if it mentions the stats.

No database migration: `values` is stored as JSON, old results simply have no `eighties` / `bestLegAverage`.

## F2 Game shot: the leg waits for the takeout

**What you asked for**
- ✅ A "Game shot" message when a leg is checked out.
- ✅ No more darts count until the takeout is done (or Autodarts is ready for the next throw).
- ✅ Then the next leg starts, or the game ends if it was the last leg.

**How it works today**
- The checkout dart ends the leg at once. The panel jumps to "Leg 2 · 501" while the darts are still in the board.
- On the last leg the game ends at once, straight into the result, before the darts are pulled.
- Darts thrown after the checkout in the same visit are already ignored by the scoring, but the dart boxes still
  take them and nothing tells you why they don't count.

**Plan**
1. `x01.ts`: when the checkout is in the turn still on the board (`open`), the state says `gameShot: true`. The leg
   is counted as won (match average, legs, darts per leg update right away), but `over` and the next leg wait until
   the turn is closed.
2. `GameResult` gets `gameShot?: boolean`; Solo Leg and Big Fish pass it on. `done` is only true once the Game shot
   is over, so the last leg also waits for the takeout before the result shows.
3. `session.svelte.ts`: like a bust, a Game shot ends the turn: no darts by hand, darts from Autodarts in that turn
   don't count. The turn closes on the takeout (`turnEnded`), on "Next turn", or when a first dart of a new turn
   arrives (takeout missed, e.g. after a reconnect), the same rules the bust already uses.
4. Screen while the Game shot lasts:
   - ✅ **Overlay on the board** (not a stamp that fades): the board dims, on top of it **"Game shot!"**, a lock and
     "Leg 3 next, pull your darts" / "Last leg, pull your darts" (DE: "Game Shot!", "Als Nächstes Leg 3, Darts
     ziehen" / "Letztes Leg, Darts ziehen"). It makes clear the board is locked: darts thrown now don't count.
   - ✅ It stays until the takeout is finished, then unlocks (fades out) and the next leg starts. ✅ While Autodarts
     sees the hand pulling the darts (`takeoutInProgress`) the lock shows the same pull animation as the status icon.
   - ✅ The overlay comes in with the existing great-turn motion; a Ton out or an n-darter shows its text as a line
     under "Game shot!" instead of a separate stamp. With animations off it simply appears and disappears.
   - ✅ The checkout dart stays in the boxes, the boxes after it are closed (like after a bust). No targets on the board.
   - Built as a component over `Board.svelte` in the game screen, driven by `result.gameShot`, not by the fx queue,
     so it can't be skipped or dropped like a moment.
5. Time cap: if the time runs out during the Game shot, the game ends as today, the leg is already counted.
6. Tests (session + x01): checkout on dart 1/2/3, darts after the checkout ignored, next leg after `turnEnded`,
   last leg only `done` after the takeout, "Next turn" ends the Game shot.

**Assumptions** (confirmed)
- ✅ Big Fish (170) gets the same Game shot, since it plays legs the same way.
- ✅ Without Autodarts (darts set by hand), "Next turn" ends the Game shot.

### Bob's 27: hit rate and score ✅

- **Hit rate** 5 → 50 %, 70 % of the game index (same doubles scale as everywhere).
- **Score** 0 → 862, 30 % of the game index. 862 is 60 % of the maximum 1437 (27 + 3 × 420 for D1–D20 + 3 × 50 for
  the bull). Below zero counts as 0.
- The score is the average of the **finished** games (`bob-27.ts` saves a new `finishedScore`): with a time cap a new
  game starts after each one, and a game cut off by the clock has an incomplete score.
- `dpi.ts`: a metric whose value is missing is left out and the other weights are scaled up, instead of counting as
  0. So a result without a finished game (and every old result, which has no `finishedScore`) is rated on the hit
  rate alone. Test for this.

## F5 Plan B (complex doubles): every dart has a target

**What you asked for**
- ✅ The success rate stays as it is: a round (one visit) is a success when the double is checked out with dart 1, 2
  or 3. (It is not weighted: a first-dart and a third-dart checkout both count 1. How many came with dart 1 / 2 / 3 is
  saved separately.)
- ✅ After a hit the visit goes on, the new target is half of it: D20 hit → D10 → D5.
- ✅ No dart is wasted, the rhythm matters: every dart has a target, you never have to pull darts early.
- ✅ New stat: **hit rate**, darts that hit the double shown ÷ darts thrown at a double.

**Example** (target D20)

| Dart | Target | Throw | Left | Next target |
| --- | --- | --- | --- | --- |
| 1 | D20 (40) | D20 | 20 | D10 · round is a success |
| 2 | D10 (20) | S4 | 16 | D8 |
| 3 | D8 (16) | … | | |

**Rules for the next target**
1. Hit → half of the double hit (D20 → D10 → D5; D5 hit leaves 5, see 3).
2. Miss with an even leave of 2–40 → that double (as today).
3. Odd leave before dart 3 → a set-up dart. 🔶 Its target is the first dart of the checkout route for that leave (the
   routes "Show route" already uses, e.g. 37 → S5 for D16), so it is shown and highlighted too. It doesn't count for
   the hit rate.
4. Odd leave for dart 3 → bull (as today).
5. ✅ Bust (1 or less left) → the next dart starts over at the main target (D20), in the same visit.

**Counting**
- Success rate, rounds and successes: unchanged, only the first checkout of a visit decides the round. A bust before
  that loses the round, as today; 🔶 darts after the restart then only count for the hit rate.
- Hit rate: every dart aimed at a double or the bull counts. Saved as `hitRate`, `doubleDarts`, `doubleHits`;
  shown in the panel under the success rate. Not in the DPI.
- ✅ Three hits in one visit (D20 → D10 → D5) plays the existing "3 in a row!" moment (today Clockwork's text,
  moves to a shared `game.threeInARow`). The "First dart!" moment stays for a first-dart checkout; the stronger one
  wins on the same visit.

**Plan**
1. `evalRound` → `evalVisit`: walks all three darts with the rules above, returns the round outcome, the target of
   every dart and its hit, and the target for the next dart.
2. Focus and board highlight show the next dart's target at all times (today: "Success" / "Missed" until the takeout).
3. Tests (hit chains, set-up, bull on dart 3, bust restart, round counting unchanged), EN/DE texts (blurb explains
   the halving and the restart).
